Setting Up Free DNS with Cloudflare

published 2026-08-06

Why Cloudflare for DNS

Cloudflare offers free DNS hosting for any domain, regardless of where you registered it. This matters because a lot of registrars either charge for DNS management or lock you into their nameservers, which limits what you can do with your domain. With Cloudflare, you get full control over your DNS records without paying a cent, and you also get their CDN and DDoS protection layered on top. The setup process is straightforward but has a few gotchas that are not well documented, especially when you are working with free domains or non-standard TLDs.

Adding Your Domain

Sign up for a Cloudflare account and click "Add a Site." Enter your domain name. Cloudflare will scan your existing DNS records and import them automatically. Select the free plan and continue. Cloudflare will give you two nameservers. Go to your registrar and change the nameservers to the ones Cloudflare provides. The propagation typically takes anywhere from a few minutes to 48 hours, though for most TLDs it completes within an hour.

If you are using a free domain from a service like nicnames, the nameserver change works the same way. The .cyou and .bond TLDs propagate quickly, usually under 10 minutes in practice.

Using the API Instead of the Dashboard

For automation, use the Cloudflare API. Go to My Profile, then API Tokens, and create a token with "Edit zone DNS" permissions scoped to your specific zone. This gives you a token that can only modify DNS records for that one domain, which is much safer than using your global API key.

curl -X POST "https://api.cloudflare.com/client/v4/zones/{ZONE_ID}/dns_records"   -H "Authorization: Bearer {API_TOKEN}"   -H "Content-Type: application/json"   -d '{"type":"CNAME","name":"anomaly","content":"anomaly-creepernet.github.io","ttl":1,"proxied":true}'

The "proxied": true flag enables Cloudflare CDN and proxy (the orange cloud in the dashboard). For most web records you want this on. For MX records you need it off because Cloudflare does not proxy email traffic.

The Zone Apex Problem

You cannot put a CNAME record at the zone apex (the root of your domain, like cnetai.cyou). RFC 1912 explicitly forbids this because a CNAME at the root would conflict with the SOA and NS records that must exist there. This is not a Cloudflare limitation, it is a DNS protocol limitation. This matters for things like GitHub Pages, which require a CNAME record to work. You can use CNAME for subdomains like anomaly.cnetai.cyou with no issues, but you cannot point the root domain via CNAME. GitHub Pages handles this by allowing you to use A records pointing to their IPs for the apex, but this breaks if they ever change their IP addresses.

This is also why free hosting services like MyOwnFreeHost require you to change your nameservers. They need to control the apex record directly, which they cannot do via CNAME if your DNS lives elsewhere.

Setting Up MX Records

If you want email on your domain, add MX records at Cloudflare with the proxy disabled. For alwaysdata email, the records look like this:

mx1.alwaysdata.com    (priority 10)
mx2.alwaysdata.com    (priority 20)

Make sure the orange cloud is OFF for MX records. You also need SPF, DKIM, and DMARC records for proper email deliverability.

What You Get for Free

Unlimited DNS queries, unlimited records, API access, DNSSEC, and CDN proxy for web traffic. There is no catch for basic usage. Cloudflare monetizes through paid add-ons and enterprise contracts. The free tier has been genuinely free for over a decade.
