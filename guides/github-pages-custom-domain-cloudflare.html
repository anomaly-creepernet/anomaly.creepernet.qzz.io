GitHub Pages with Custom Domain on Cloudflare

published 2026-08-06

The Setup

GitHub Pages gives you a free static website at {username}.github.io or at a custom domain. The custom domain setup requires two things: a DNS record pointing your domain to GitHub servers, and a CNAME file in your repository telling GitHub which domain to serve.

Step 1: CNAME File

Create a file called CNAME (no extension) in the root of your repository with a single line:

anomaly.cnetai.cyou

GitHub reads this file and knows to serve your site at that domain instead of the default github.io address. If you are using a subdomain, GitHub automatically provisions an SSL certificate. For the apex domain you need A records instead of a CNAME.

Step 2: DNS Record at Cloudflare

For a subdomain, add a CNAME record:

Type: CNAME  Name: anomaly  Content: anomaly-creepernet.github.io  Proxy: ON

For the apex domain, use A records because CNAME at zone apex is forbidden by RFC 1912:

Type: A  Name: @  Content: 185.199.108.153  Proxy: OFF
Type: A  Name: @  Content: 185.199.109.153  Proxy: OFF
Type: A  Name: @  Content: 185.199.110.153  Proxy: OFF
Type: A  Name: @  Content: 185.199.111.153  Proxy: OFF
Turn off the Cloudflare proxy for apex A records because it can interfere with GitHub domain verification. For subdomains with CNAME, the proxy works fine and improves performance through the CDN.

Step 3: Verify and Enable HTTPS

In your GitHub repository settings, go to Pages, then Custom domain, and enter your domain. GitHub will verify it by checking the DNS record. Once verified, check "Enforce HTTPS." GitHub provisions the SSL certificate automatically, usually within a few minutes. With Cloudflare proxy enabled on a CNAME subdomain, the connection is: visitor to Cloudflare (HTTPS) to GitHub (HTTPS). Full encryption end to end.

Common Issues

  • Domain not verified: Check that the DNS record is correctly configured and wait for propagation. You can use dig anomaly.cnetai.cyou CNAME to verify the record exists.
  • HTTPS not working: Make sure the CNAME file is pushed to the default branch and the domain is verified. GitHub will not issue a certificate for an unverified domain.
  • Too many redirects: This happens when both Cloudflare and GitHub try to redirect HTTP to HTTPS. Make sure "Always Use HTTPS" is enabled in Cloudflare SSL/TLS settings.
