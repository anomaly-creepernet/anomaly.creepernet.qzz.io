Why GPT Cannot Play Chess

published 2026-08-06

The Elephant in the Room

As of August 2026, GPT-5 and GPT-5 Thinking cannot play a legal game of chess. This has been tested and documented repeatedly: GPT makes illegal moves, creates pieces that do not exist on the board, moves pieces in ways they cannot move, and sometimes produces game states that are physically impossible. A chess.com user rated between 700-1000 (beginner level) reported beating ChatGPT easily despite it attempting illegal moves multiple times, including trying to move a nonexistent queen and recapturing pieces it had already moved away from.

Why This Matters

Chess is not a hard problem for computers. A chess engine from 1998 running on a TI-89 calculator can play a perfectly legal game. Stockfish on a modern phone plays at superhuman level. The issue is not that chess is fundamentally difficult for AI. The issue is that GPT is not designed to play chess, and its architecture makes it incapable of doing so reliably, despite having ingested millions of chess games during training.

The Core Problem: No Internal Board State

GPT is a language model. It predicts the next token based on patterns in its training data. When it generates a chess move like "Nf3", it is not consulting an internal representation of a chessboard. It is producing a token sequence that statistically resembles chess notation. It has no actual understanding of where the pieces are, what the legal moves are, or what the current game state looks like.

This is fundamentally different from how a chess engine works. Stockfish maintains an explicit board state, generates legal moves from that state, evaluates positions using a search algorithm, and selects the best move. Every move it produces is guaranteed to be legal because it only considers legal moves. GPT has none of this. It is generating text that looks like chess without any of the underlying machinery that makes chess work.

The Same Model Writes Code and Builds Malware

Here is the paradox: the same model that cannot track 32 pieces on an 8x8 board can write functional Python code, produce working remote access trojans in Python with Discord C2 and PyInstaller packaging, and pass the bar exam. How is this possible?

The answer is that code generation works because there is enough pattern in training data for the model to approximate correct logic most of the time. Code has a loose feedback loop: if a function is slightly wrong, it might still compile and run with minor bugs. Chess has a strict binary feedback loop: a move is either legal or it is not. There is no "close enough" in chess. The model can hide its lack of understanding in code because bugs are not immediately obvious. In chess, every error is immediately visible and game-breaking.

The Customer Support Connection

The chess failure and the customer support behavior are two sides of the same coin. GPT cannot play chess because it does not maintain state, and it sounds like a support agent because its RLHF training optimized it for politeness and compliance rather than accuracy and capability. Both behaviors stem from the same training philosophy: optimize for what looks good in a short evaluation, not for what actually works in practice.

A model trained to be helpful in the abstract will say "I would be happy to help" instead of just helping. A model trained on text patterns will generate "Qe4" because it looks like a chess move, not because a queen is actually on that file. The surface appearance is correct. The underlying reality is hollow.

What This Means for AI Development

If you need an AI to perform tasks that require precise state tracking and deterministic rule following (games, math proofs, legal reasoning, formal verification), pure language models are the wrong tool. You need models with external state management, tool use, and explicit reasoning chains. The lesson from chess is simple: generating text that looks correct is not the same as being correct, and the gap between those two things is where LLMs fail silently.
